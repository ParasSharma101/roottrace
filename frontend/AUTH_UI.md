# Authentication presentation

Updated 2026-11-19 from the user's supplied reference: white form area, deep teal panel, restrained typography and clearer labels. RootTrace branding and an explicitly illustrative investigation replace the sample's testimonials, customer logos and unsupported social-login controls. CSS and existing Lucide icons supply the artwork; no dependencies, fonts or images were downloaded.

`AppFrame` renders login, signup, forgotten-password, reset-password and verification routes in the public authentication shell. Private routes use the workspace shell described in WORKSPACE_UX.md. `AuthShell` shares the responsive composition; `AuthField` and `AuthPasswordField` supply associated labels, autocomplete, focus treatment and password visibility. `src/app/auth.css` scopes styles, native input/autofill colors and reduced-motion handling to the new pages. At widths up to 900px the form becomes a single column; phones use natural vertical scrolling.

Existing login/signup/demo functions, password validation and backend account rules remain unchanged. Signup now enters the selected workspace overview; login retains explicit workspace selection. Loading prevents duplicate submission; errors use alerts. No database or backend change is involved. Visual browser checks covered desktop and 390px-wide signup, associated labels, visibility toggle and the sign-up link, without submitting credentials or creating accounts. A temporary preview tab became unavailable after mobile inspection; its viewport override was reset. The saved desktop screenshot is a local review artifact outside Git.

The verification panel now distinguishes request acknowledgement from delivery and refreshes pending/running status every three seconds for at most ten checks. Local development on loopback hosts shows an optional Mailpit link and explains that captured test messages do not arrive in Gmail. Production builds omit this hint. Diagnosis read only delivery metadata and Mailpit subjects/counts, never verification proofs or bodies. The user completes verification from the local inbox.

Validation: TypeScript, thirteen existing auth/membership protocol tests and the production Next.js build passed. Build validation used a source copy under ignored `backend/target` with a node_modules junction, preserving the running development server's `.next`. Backend tests were not repeated for these frontend-only changes. Actual account submission and email confirmation were not performed through the browser.
